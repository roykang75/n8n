# ISSUE-121419: Workflow Creation Error Analysis

## 1. Issue Description
**Error Message:** `java.lang.ClassCastException: class java.util.LinkedHashMap cannot be cast to class java.lang.String`
**Endpoint:** `POST /rest/workflows`
**Scenario:** Creating a new workflow with standard payload (including `settings` and `meta` objects).
**Impact:** Unable to create or save workflows; blocks core functionality.

## 2. Root Cause Analysis
Initial investigation pointed to a JSON deserialization issue where a JSON Object (parsed as `LinkedHashMap` by Jackson) was being incorrectly cast to a `String` field in the Java backend.

However, after extensive refactoring and testing, the evidence strongly suggests that **the running application is not reflecting the latest code changes**. Despite numerous code modifications designed to bypass this specific error (e.g., changing fields to `Object`, forcing default values), the error persists identically, and debug logs added to the codebase do not appear in the output.

## 3. Detailed Timeline of Attempts

### Attempt 1: DTO Refactoring (Initial Fix)
- **Action:** Replaced manual `Map<String, Object>` parsing in `WorkflowController` with a strongly typed `CreateWorkflowRequest` DTO.
- **Goal:** Leverage Jackson's automatic deserialization handling.
- **Result:** Failed. Error persisted.

### Attempt 2: Enhanced DTO Configuration
- **Action:** Added `@JsonIgnoreProperties(ignoreUnknown = true)` to all DTOs and Inner Classes (`WorkflowSettings`, `WorkflowMeta`).
- **Action:** Mapped `tags` field explicitly using `@JsonProperty("tags")` and added logic to handle `List<Object>` (mixed Map/String types).
- **Goal:** Handle potential schema mismatches or extra fields from the frontend.
- **Result:** Failed. Error persisted.

### Attempt 3: Type Safety Relaxation (Using `Object`)
- **Action:** Changed `settings` and `meta` fields in `CreateWorkflowRequest` from specific types to `Object`.
- **Action:** Implemented manual conversion using `ObjectMapper.convertValue()` inside `toServiceRequest()`.
- **Goal:** Prevent Jackson from attempting any implicit casting during the initial binding phase.
- **Result:** Failed. Error persisted.

### Attempt 4: Debug Logging & Verification
- **Action:** Added explicit logs (`VERSION 2`, `VERSION 3`) and `System.out.println` to `WorkflowController` entry points.
- **Goal:** Verify that the new code is being executed.
- **Observation:** **Logs did not appear in the output.** Only standard Spring Boot startup logs were visible.

### Attempt 5: Hardcoded Bypass (Force Defaults)
- **Action:** Modified the code to completely ignore the incoming `settings` and `meta` payload, forcing `new WorkflowSettings()` (default Java objects).
- **Goal:** Prove that the incoming data structure is causing the issue.
- **Result:** **Failed. The error persisted accurately.** This is logically impossible if the new code was running, as the failing payload data was no longer being touched.

### Attempt 6: Controller Signature Reversion
- **Action:** Reverted `WorkflowController.createWorkflow` signature to accept `Map<String, Object>` again, moving DTO conversion inside the method.
- **Goal:** Bypass any potential Spring MVC Argument Resolver issues.
- **Result:** Failed.

## 4. Key Observations
1.  **Partial Success with Simple Payload:** A request *without* the `settings` field (`{"name": "Simple"}`) succeeds. This implies the legacy code (or hidden code) handles basic fields but crashes on complex objects like `settings`.
2.  **Reference to `Simple Test`:** Confirmed that the server is responsive and database writes work for simple cases.
3.  **Logs Missing:** No debug logs (`VERSION X`) appeared, confirming the running bytecode does not match the source code.

## 5. Conclusion & Recommendation
The development environment (Gradle build/cache or the running process) is stuck in a state where it is not repackaging the modified `WorkflowController` class effectively, or `bootRun`/`java -jar` is serving cached artifacts.

**Recommended Action:**
1.  **Full Environment Clean:**
    ```bash
    ./gradlew clean --no-daemon
    rm -rf springboot/build
    ```
2.  **Restart via Standard Script:**
    Use the provided `start-dev.sh` to ensure the correct build lifecycle is triggered.
    ```bash

    ```
